# 남은 검증 과제 (research backlog)

`docs/strategy.md` §2.10–§2.11 이 전이 장치(`minimum_duration_days`,
`hysteresis`)를 사후 측정하고 **낙폭 축의 논증을 철회**하면서 남긴 과제들이다.
이 문서는 **새 세션이 맥락 없이 읽고 바로 시작할 수 있도록** 쓰였다.

전부 **사후 측정**이다. `config/` 는 v1.0-frozen 이고 이 backlog 의 어떤 항목도
설정을 바꾸지 않는다. 바꿀 근거가 나오면 그때는 **새 freeze** 절차(§4)를 밟는다.

## 0. 시작 전 준비

### 0.1 전체 이력 DB 를 다시 만든다 (필수)

`data/fear_ladder.db` 는 **5년치만** 들어 있다(2021-09-15 …). 운영용이고
커밋되어 있으며 의도적으로 pruned 되어 있다. 여기 있는 모든 측정은 30년
이력이 필요하므로 **저장소 밖에** 따로 만들어야 한다.

```bash
python scripts/collect_full_history.py --out /path/outside/repo/full.db
```

몇 분 걸리고 외부 provider 를 호출한다. 한 세션 동안 재사용하라.
이 스크립트는 운영 DB 로 쓰는 것을 **거부한다** — 과거에 pruned DB 로 리포트를
재생성해 30년 수치(CAGR 18.88%)를 5년 수치(14.62%)로 덮은 사고가 있었고,
`scripts/make_performance_report.py` 도 같은 이유로 가드를 갖고 있다.

완성되면 이렇게 나와야 한다(핵심은 마지막 두 줄의 경계 날짜):

```text
QLD   7753 rows  1996-01-02 .. 2026-09-15
QQQ   7753 rows  1996-01-02 .. 2026-09-15
TQQQ  7753 rows  1996-01-02 .. 2026-09-15
leveraged sleeves are real prices from 2010-02-11 onward
```

## 2. 이미 아는 것 (다시 재지 말 것)

§2.10–§2.11 의 결론 요약. 재현 명령은 각 절에 있다.

- **`minimum_duration_days = 75`** — 성과 축에서는 어떤 값도 구별되지 않는다.
  탐색창의 "낙폭 최소" 는 **전부 2010-02-11 이전**, 즉 재구성 가격 구간에서 나온
  것이었다. 실물 구간에서는 75가 아홉 중 **낙폭 꼴찌**이고 창 간 순위 상관은
  0(탐색-검증 +0.17) 또는 음수(탐색-OOS −0.37, 검증-OOS −0.40)다.
  **남는 근거는 회전율뿐**이고 그것은 단조다(d=20 → 173회, d=75 → 53회).
- **`hysteresis = 5.0`** — 톱니. h=2 가 금융위기에서 h=5 를 17%p 앞서고
  닷컴·OOS 에서는 진다. 방향이 창마다 뒤집히므로 바꿀 근거 없음.
- **`confirmation_days = 1`** — 평활(3/5/10/20일)은 **모든 구간에서 낙폭을
  악화**시킨다. 이 사다리는 공포에 먼저 들어가는 장치라 지속성 요구가 손해다.
- **`trend_filter.max_leverage_below = 0.5x`** — `d`·`h` 와 달리 **단조**이고
  실제 효과다. 대폭락에서 0.25 칸당 낙폭 약 10%p, 잔잔한 실물 구간에서는 1%p.
  **현재 전략의 최대 미검증 노출.**
- 전략 전체 최대낙폭 −62.4% 는 2000-03-27 → 2002-10-09, **재구성 가격 구간**.
  실물 구간 최대낙폭은 −46.6%, 2021-11-19 → 2023-03-10 이고 회복에 2.3년.
- 2020년 3월은 이 전략에서 −25% 국면조차 만들지 못했다(추세 필터가 작동).

### 기준 수치 (무언가 어긋나면 이걸로 확인한다)

고정 설정, 전 구간 1996–2026: **CAGR 18.78% / MDD −62.4% / Sharpe 0.64 /
단계 변경 93회**. 실물 구간 2010-02-11–: **25.83% / −46.6% / 0.88 / 53회**.

## 3. 후보 과제

권장 순서대로. 각 항목은 독립적이므로 골라 해도 된다.

### TASK-181 재구성 모델을 2008년 실물 QLD 로 검증한다 — **1순위**

**질문.** §2.11 의 결론은 "대폭락 증거가 모델 가격 하나뿐" 이라는 데 걸려 있다.
그 모델이 **폭락기에** 얼마나 정확한가?

**왜 지금 할 수 있는가.** QLD 는 2006-06-21 상장이라 **2008년 폭락을 실물
가격으로 겪었다.** 확인된 사실:

| | 2007–2009 최대낙폭 | |
| --- | --- | --- |
| QQQ | −53.6% (2008-11-20) | 실물 |
| **QLD** | **−84.0%** (2009-03-09) | **실물** |
| TQQQ | −94.6% (2009-03-09) | 재구성 |

즉 **2배 슬리브에 대해서는 50% 이상 지수 하락을 실물로 관측할 수 있다.**

**무엇을 하는가.** `SyntheticLeveragedProvider` 로 2006-2009 구간 QLD 를
재구성한 뒤 실물 QLD 와 비교한다. 핵심은 **폭락 구간에 한정한** 오차다.
`src/fear_ladder/data/collectors/synthetic.py` 의 docstring 이 이미 전체 수명
기준 오차를 적어 두었다(QLD R² 0.990, 누적 −1.5% / TQQQ R² 0.997, −8.3%).
**그 숫자는 잔잔한 기간이 지배한다 — 폭락기만 잘라 잰 적이 없다.**

**판단 기준.** 폭락 구간 누적 오차가 전체 수명 오차와 비슷하면 §2.11 의
−62.4% 는 신뢰할 만하다. 폭락기에 오차가 크게 벌어지면(특히 모델이 손실을
**과소평가**하는 방향이면) §2.11 의 결론을 그만큼 더 보수적으로 고쳐야 한다.

**주의.** 레버리지가 높을수록 오차가 커지므로 QLD(2x)에서 잰 오차를 TQQQ(3x)에
그대로 적용하면 안 된다. 상한 추정으로만 쓰고 그렇게 적어라.

### TASK-182 S&P 500 에서 재현되는가 — 유일하게 독립인 데이터

**질문.** 시간 창은 전부 소진됐다(§2.8). 독립성이 남아 있는 축은 **다른 시장**뿐이다.

**확인된 상장일** (FinanceDataReader 로 검증함):

| | 상장 | 2008년 폭락 | 2000년 폭락 |
| --- | --- | --- | --- |
| SPY | 1993-01-29 | 실물 | 실물 |
| SSO (2x) | 2006-06-21 | **실물** | 재구성 |
| UPRO (3x) | **2009-06-25** | 재구성 | 재구성 |

**정정 주의**: UPRO 는 2009년 6월 상장이라 **2008년을 겪지 않았다.** 이전 세션에서
"SSO/UPRO 가 2008년에 실물로 존재한다" 고 적은 것은 SSO 에만 해당한다.

**무엇을 하는가.** 같은 전략을 SPY/SSO/UPRO 로 돌린다. `max_leverage_below` 의
**단조성이 재현되는지**가 핵심 질문이다 — 재현되면 그건 노이즈가 아니라 구조다.
`d`·`h` 가 여기서도 톱니면 §2.11 의 판정이 시장을 건너 확인된다.

**품.** 앞의 과제들보다 크다. 지수 재구성(`FRED:SP500` 계열)과 설정 분기가
필요하다. 반나절 규모.

**주의.** 지표 임계값은 나스닥100 으로 탐색된 값이다. S&P 에서 성적이 나쁘게
나와도 그것이 곧 "전략이 틀렸다" 는 아니다. 보는 것은 **절대 성적이 아니라
파라미터 반응의 모양**이다.

### TASK-183 `score.weights` — 지표를 하나씩 빼 본다

**질문.** 20개 지표 가중치는 파라미터 개수로는 가장 큰 미검증 표면인데 아무도
흔들어본 적이 없다. 지지도 '보통'.

**무엇을 하는가.** 가중치를 미세조정하지 말고 **지표를 하나씩 제거**한다
(20회 실행). "이 지표가 없으면 성과가 무너지는가" 에 답이 나온다.

**판단 기준.** 살아남는 지표가 3~4개뿐이라면 나머지 16개는 복잡도와 데이터
의존성만 더하는 셈이다. 그 자체로 가치 있는 결론이다 — §2.6 이 지표 정규화에서
내린 판단과 같은 종류다.

**주의.** 제거는 **가중치 재정규화**를 동반해야 한다. 그냥 0으로 두면 종합
점수의 척도가 바뀌어 밴드 경계(`regime.boundaries`)의 의미가 달라진다.

### TASK-184 이벤트 단위 분석 — 표본이 1인 문제

**질문.** 지금까지의 모든 비교는 30년을 CAGR 하나로 압축했다. **관측이 사실상
1개**다. 창을 나눠도 3개다.

**무엇을 하는가.** 93번의 단계 변경 각각에 대해 "이 전환이 얼마를 벌거나
잃었나" 를 잰다. 경로 하나가 **93개 관측의 분포**가 되고, 파라미터 값 사이의
짝지은 비교(paired comparison)가 가능해진다.

**왜 값진가.** 지금까지의 어떤 측정보다 통계적으로 정직하다. "75가 120보다
낫다" 같은 주장에 처음으로 **분산**을 붙일 수 있다.

**주의.** 이벤트 수익을 어떻게 귀속시킬지가 설계의 전부다. 전환 시점부터 다음
전환까지의 구간 수익을 쓰되, **추세 필터가 그 사이에 개입한 구간**을 어떻게
다룰지 먼저 정하고 문서에 적어라.

### TASK-185 비용 모델 — 가장 싼 확인

**질문.** `config/strategy.yaml` 에 `commission_bps: 10.0`, `spread_bps: 0.0`,
`slippage_bps: 0.0`. 코드는 스프레드와 슬리피지를 지원하는데 **둘 다 0**이고
지지도 표에 항목 자체가 없다.

**무엇을 하는가.** 현실적인 값(TQQQ 스프레드, 폭락기 슬리피지 확대)을 넣고
다시 돌린다.

**예상.** 거래가 드물어(30년 93회) 영향은 작을 것이다. 하지만 **한 번도 재본
적이 없다**는 것이 문제다. 확인 비용이 가장 싸므로 다른 과제의 곁가지로 해도 된다.

## 4. 결과를 기록하는 방법

이 저장소의 관행이다. §2.10–§2.11 이 그 예시다.

1. **스크립트로 만든다.** 스크래치 파일로 끝내지 않는다 — 문서의 모든 표는
   재현 명령을 갖는다. `scripts/tail_risk.py` 를 본보기로 삼아라.
2. **리포트를 `reports/` 에 커밋한다.** 대시보드가 있으면 읽어서 보여준다
   (`app/views/common.py` 의 `SENSITIVITY_REPORTS`). 리포트가 없으면 해당 구역을
   조용히 생략하도록 되어 있으니, 없는 상태에서도 앱이 깨지지 않는지 확인하라.
3. **`docs/strategy.md` 에 절을 추가한다.** 제목에 날짜와 **"사후 측정 — 아무것도
   바꾸지 않음"** 을 명시한다. §2.5 의 지지도 표도 같이 갱신한다.
4. **이전 결론이 틀렸으면 철회를 눈에 보이게 적는다.** §2.10 의 정정 블록이
   본보기다. 조용히 고쳐 쓰지 않는다 — 무엇이 왜 틀렸는지 남긴다.
5. **테스트를 붙인다.** `tests/unit/test_tail_risk.py`,
   `test_transition_sensitivity.py` 가 본보기다. 검증할 것은 보통 두 가지다:
   변형이 고정 설정을 오염시키지 않는가, 그리고 변환이 미래를 보지 않는가.
6. **CI 는 `ruff check src tests scripts app` 을 돈다** (`ruff format` 은 아니다).
